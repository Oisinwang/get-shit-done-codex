# 提示词配方

安装 GSD Codex 后，可以把这些内容粘贴到 Codex。它们是给 Codex 的提示词，不是 shell 脚本：每一段都会告诉 Codex 应该使用哪条 GSD 路径、检查哪些状态、留下什么证据。

运行前先替换方括号里的占位内容。

## 启动新项目

适用于只有想法、还没有持久项目状态的情况。

```text
我想构建 [目标]。请使用 GSD Codex 把它转成持久项目状态。

运行 `$gsd-new-project --auto`，检查生成的 `.planning/PROJECT.md`、`.planning/ROADMAP.md` 和 `.planning/STATE.md`，然后继续运行 `$gsd-next`。

第一阶段保持小范围。不要跳过验证。在说工作完成之前，展示验证证据和变更文件。
```

## 现有仓库

适用于仓库里已经有代码、测试和 README 的情况。

```text
在这个现有仓库里规划新工作之前，请先用 GSD Codex 理解代码库。

先运行 `$gsd-map-codebase`，再运行 `$gsd-new-project --auto`，然后运行 `$gsd-discuss-phase 1`。提出实现工作前，请使用已发现的项目约定。

保留现有用户改动。保持 `.planning/` 状态可读，并在任何提交前展示验证证据。
```

## 小修复

适用于任务范围很窄，但仍然需要可追踪验证的情况。

```text
用 GSD Codex 处理一个小修复：[具体 bug 或小改进]。

运行 `$gsd-fast "[具体 bug 或小改进]"`。保持变更聚焦，新增或更新最小有用测试，不要跳过验证。

修复后，总结行为变化、测试证据和剩余风险。
```

## 恢复工作

适用于中断、上下文压缩，或从另一个会话交接之后。

```text
用 GSD Codex 恢复当前项目。

运行 `$gsd-resume-work`，然后运行 `$gsd-progress --forensic`。在提出下一步之前，读取 `.planning/STATE.md` 和当前阶段 artifacts。

不要从聊天记忆里重建计划。请从已保存的项目状态继续，并指出任何需要我输入的 blocker。
```

## 审计并修复

适用于你还没有预先指定任务，但希望 Codex 找出并修复影响可维护性或发布准备度的问题。

```text
使用 GSD Codex 审计这个仓库，找出会影响安装、文档、测试、发布安全或首次用户体验的实际问题。

运行 `$gsd-audit-fix`。按影响程度分类问题，只修复高置信度事项；风险更高的想法请留下 notes 或 issues，不要强行改动。

每个修复都保持补丁小范围，保留 `.planning/` 证据，不要跳过验证，并展示证明结果的命令。
```

## 如何选择

| 情况 | 从这里开始 |
|------|------------|
| 新想法或产品目标 | 启动新项目 |
| 现有代码库需要先建立上下文 | 现有仓库 |
| 一个聚焦的 bug 或文档修复 | 小修复 |
| 已经有之前的 GSD 工作 | 恢复工作 |
| 还没有选定任务 | 审计并修复 |
