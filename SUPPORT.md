# Support

Use the channel that matches what you need. This keeps public issues actionable and keeps private reports private.

## Questions and usage help

Use GitHub Discussions for setup questions, workflow advice, troubleshooting help, and examples:

https://github.com/Oisinwang/get-shit-done-codex/discussions

Before posting, include:
- Your runtime: Codex, Claude Code compatibility, Gemini CLI, OpenCode, or another supported runtime
- Your install method: `npx`, global install, local source checkout, or manual update
- The command you ran and the exact output or error text
- Whether you are using the public branch `codex/bootstrap`

## Bug reports

Use the issue chooser for reproducible bugs:

https://github.com/Oisinwang/get-shit-done-codex/issues/new/choose

Choose "Bug Report" and include the smallest reproduction you can. Bugs should describe behavior that is wrong in the current Codex-first fork, not questions about how to use a workflow.

## Feature and enhancement proposals

Open a feature or enhancement issue only when you have a concrete proposal that fits the contribution rules:

https://github.com/Oisinwang/get-shit-done-codex/issues/new/choose

Read `CONTRIBUTING.md` first. Feature and enhancement PRs need an approved issue before code is written.

## Security vulnerabilities

Do not report security vulnerabilities in public issues, pull requests, discussions, or social channels.

Use GitHub private vulnerability reporting:

https://github.com/Oisinwang/get-shit-done-codex/security/advisories/new

If the private advisory form is unavailable, open a public issue that says only "I need to report a security vulnerability privately" and wait for maintainer guidance.

## Conduct issues

For conduct concerns, follow `CODE_OF_CONDUCT.md`. Do not include sensitive personal details in public issues, pull requests, or discussions.
